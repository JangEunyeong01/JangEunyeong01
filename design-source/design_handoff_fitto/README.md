# Handoff: Fitto — 건강관리 앱 (모바일)

## Overview
Fitto(피또)는 물방울 요정 캐릭터가 사용자의 건강 상태를 "숫자보다 표정으로" 알려주는 개인 건강관리 앱이다.
칼로리·물 섭취·활동/걸음·운동·생리 주기를 한 화면에서 관리하고, 사용자가 고른 캐릭터 성격(친근/엄격/중립)에 따라 모든 안내 문구의 말투가 바뀐다.
비주얼 언어는 **글래스모피즘**(반투명 카드 + backdrop blur + 흰 테두리 + 부드러운 그림자)이며, 시간대에 따라 화면 상단 그라데이션 색이 변한다.

## About the Design Files
이 번들에 들어 있는 HTML 파일은 **디자인 레퍼런스**다. 의도한 화면 구성·색·타이포·인터랙션을 보여주는 프로토타입이며, 그대로 가져다 쓰는 프로덕션 코드가 아니다.
할 일은 이 HTML 디자인을 **대상 코드베이스의 기존 환경**(React Native / Flutter / SwiftUI / 웹 등)에서 그 환경의 관례와 라이브러리로 **다시 구현**하는 것이다.
아직 환경이 없다면 프로젝트에 가장 적합한 프레임워크를 골라 구현한다. 모바일 앱이 목표이므로 React Native(Expo) 또는 Flutter를 권장한다.

- `Fitto App.dc.html` — 원본 디자인 소스. 커스텀 런타임(support.js) 위에서 동작하므로 **코드 구조를 모방하지 말고 결과 화면만 참고**할 것.
- `Fitto 건강관리 앱.html` — 오프라인 단독 실행 버전. 브라우저로 열어 실제로 눌러보며 동작을 확인하는 용도. **이걸 먼저 열어볼 것.**
- `assets/fitto-hello.png`, `assets/fitto-face.png` — 캐릭터 이미지(전신/얼굴). 사용자 손그림을 배경 제거·보정한 임시 에셋이며, 최종 일러스트가 준비되면 교체 대상이다.

프로토타입 좌우에 있는 **왼쪽 칩 패널(화면/테마/성격/3안/시간대 전환)과 Android 기기 프레임은 디자인 검토용 하네스이며 앱에 구현하지 않는다.** 구현 대상은 기기 프레임 안쪽 화면뿐이다.

## Fidelity
**High-fidelity (hifi)**. 색·타이포·간격·라운드·그림자·인터랙션이 모두 확정값이다. 아래 디자인 토큰과 화면 명세의 수치를 그대로 재현할 것.
단, 캐릭터 일러스트는 임시 에셋이므로 최종 아트가 오면 교체한다(레이아웃·크기는 그대로).

## 시간대 헤더 그라데이션
화면 상단에 시간대별 색의 그라데이션 레이어가 깔린다(포인터 이벤트 없음). 6개 시간대:

| 시간대 | 색 | 인사말 |
|---|---|---|
| 새벽 dawn | `#2C3E50` | 좋은 새벽 |
| 아침 morning | `#FFCBB6` | 좋은 아침 |
| 낮 day | `#89C4E1` | 좋은 오후 |
| 오후 after | `#A8D8B9` | 나른한 오후 |
| 저녁 evening | `#C4B5E8` | 편안한 저녁 |
| 밤 night | `#6B5B95` | 늦은 밤 |

**세 가지 안이 프로토타입에 들어 있고, 구현 기본값은 A(페이드)다.**
- **A 페이드(기본)**: 높이 300px, `linear-gradient(180deg, C40% → C13% 42% → transparent)`.
- B 오브: 높이 340px 옅은 페이드 + 좌상단 280px 블러 오브(색상 C) + 우측 230px 민트 오브, 각 `blur(26px)`.
- C 물결: 높이 250px 진한 페이드에 하단을 타원으로 깎음(`border-radius: 0 0 46% 46% / 0 0 22% 22%`) + 아래 70px 라디얼 이음선.

실제 앱에서는 시간대를 기기 시각으로 자동 판정한다(프로토타입에서는 헤더 우측 칩으로 수동 순환).

## 캐릭터 상태 규칙 (매우 중요)
물 섭취 진행도를 5단계로 나누고, 단계에 따라 캐릭터의 **채도·크기·부유 속도**와 **문구**가 바뀐다.
단계 인덱스 = `min(4, floor(현재물량 / 목표물량 * 5))`.

| 단계 | 이름 | 이미지 필터 | scale | 부유 |
|---|---|---|---|---|
| 0 | 바싹 마름 | `grayscale(.5) saturate(.55) brightness(1.04)` | 0.90 | 정지 |
| 1 | 목마름 | `grayscale(.22) saturate(.8)` | 0.94 | 7s |
| 2 | 보통 | `saturate(1)` | 1.00 | 5.5s |
| 3 | 촉촉 | `saturate(1.18) brightness(1.03)` | 1.03 | 4.2s |
| 4 | 완전 만족 | `saturate(1.32) brightness(1.06)` | 1.06 | 3.2s |

전환은 `filter .4s ease, transform .4s ease`.
최종 일러스트가 5장 준비되면 필터 대신 **이미지 스왑**으로 구현하는 것이 바람직하다(레이아웃 동일).

### 성격별 문구 (3종, 사용자가 설정에서 변경)
성격은 앱 전체 문구에 일관되게 적용된다. 아래 값이 확정 카피다. `{}` 는 런타임 수치.

**친근형 (friendly)**
- 홈 인사: `오늘도 같이 힘내볼까요? 물 {남은물}ml만 더 마시면 완전 만족이에요!`
- 칼로리: `아직 {남은kcal}kcal 남았어요. 저녁은 편하게 드셔도 괜찮아요 :)`
- 운동: `어제 많이 걸으셨으니 오늘은 가볍게 몸 풀어요!`
- 생리: `3일차예요. 오늘은 무리하지 말고 따뜻하게 있어요.`
- 드러눕기 제목/본문: `피또가 드러누웠어요` / `3일 동안 운동 기록이 없어요. 같이 5분만 걸어볼까요? 저도 일어날게요!`
- 생일: `{닉네임}님, 생일 축하해요! 오늘은 케이크 한 조각쯤 괜찮아요. 목표도 살짝 늘려뒀어요 🎂`
- 물 알림: `"물 마실 시간이에요! 한 잔이면 촉촉해질 수 있어요 💧"`
- 5단계 멘트: 바싹마름 `입이 바싹 말랐어요… 한 잔만 부탁해요!` / 목마름 `아직 목이 말라요. 같이 한 잔 어때요?` / 보통 `좋아요, 이 페이스면 괜찮아요!` / 촉촉 `거의 다 왔어요! 한 잔만 더요.` / 완전만족 `완전 만족! 오늘 물은 합격이에요 ✨`

**엄격형 (strict)**
- 홈 인사: `오늘 목표까지 {남은kcal}kcal 남았습니다. 물은 {남은물}ml 부족합니다.`
- 칼로리: `섭취 {섭취kcal}kcal. 목표 대비 {퍼센트}%입니다.`
- 운동: `목표는 체중 감량입니다. 유산소 20분을 채우세요.`
- 생리: `3일차. 강도 높은 운동은 권장하지 않습니다.`
- 드러눕기: `3일간 운동 기록 없음` / `기록이 없으면 계획을 조정할 수 없습니다. 오늘 5분이라도 채우세요.`
- 생일: `{닉네임}님, 생일 축하합니다. 오늘은 목표를 조금 여유롭게 잡아두었습니다.`
- 물 알림: `"수분 섭취가 2시간째 없습니다. 지금 250ml 채우세요."`
- 5단계 멘트: `수분 섭취가 심각하게 부족합니다.` / `목표의 절반도 못 채웠습니다.` / `평균 수준입니다. 계속 유지하세요.` / `목표까지 얼마 남지 않았습니다.` / `목표 달성. 내일도 같은 페이스로.`

**중립형 (neutral)**
- 홈 인사: `오늘 섭취 {섭취kcal}kcal, 물 {현재물}ml입니다.`
- 칼로리: `남은 칼로리 {남은kcal}kcal.`
- 운동: `추천 운동 2개가 있습니다.`
- 생리: `생리 3일차입니다.`
- 드러눕기: `운동 기록 3일 없음` / `운동 기록이 3일간 없습니다. 가벼운 걷기를 추천합니다.`
- 생일: `{닉네임}님의 생일입니다. 오늘 목표 칼로리에 200kcal을 더했습니다.`
- 물 알림: `"물 섭취 알림 · 목표까지 950ml 남음"`
- 5단계 멘트: `수분 섭취 20% 이하.` / `수분 섭취 부족 상태.` / `수분 섭취 보통.` / `목표 근접.` / `목표 달성.`

## Navigation

### 탭바 (기본안 = B)
하단 플로팅 글래스 바. 위치 `left/right 12px, bottom 12px`, 높이 64px, padding 7px, radius 22px, `blur(24px) saturate(1.6)`, 그림자 `0 12px 30px rgba(44,62,80,.16)`.
선택된 탭: 주 버튼 그라데이션 배경 + 흰 글씨 700 + 그림자. 비선택: 투명 배경 + sub 색 500.
각 탭 = 위 6px 점(선택 시 흰색, 비선택 시 sub 50% 투명) + 11.5px 라벨, 세로 배치.

프로토타입에 3안이 있고 **구현 기본값은 B**:
- A 4탭 균등: 홈 · 식단 · 헬스 · 설정.
- **B 4탭 + 중앙 FAB(기본)**: 홈 · 식단 — [+ FAB] — 헬스 · 설정. FAB는 56×50, radius 18px, 그라데이션, 세로 중앙 정렬. 탭하면 **빠른 기록 시트**(물 +250ml / 음식 기록 / 운동 기록 / 체중 기록)가 올라온다. 가장 자주 하는 행동이 기록이므로 이 안을 권장.
- C 5탭: 홈 · 식단 · 헬스 · 리포트 · 설정.

- **월간 선택 시 기간 바**: ‹ › 로 월 이동, 프리셋 칩(한 달 / 최근 3개월 / 최근 6개월 / 직접 선택). 직접 선택은 시작·종료 월 입력(최대 12개월). 라벨은 단월이면 `2026년 8월`, 복수면 `5월 – 8월 (4개월)`.
- 요약 카드: 큰 수치 + 목표 + 기간 설명(일간 `오늘` / 주간 `이번 주 7일 평균` / 월간 `{기간} 평균`).
- 막대 차트: 기간별 라벨·값(일간 = 시간대, 주간 = 요일, 월간 단월 = 1~4주, 복수월 = 월별). 최대값 기준 스케일, 값 위에 라벨.
- 물 상세에는 **목표량·1회 컵 용량 직접 설정**(목표 500–4000ml, 컵 100/200/250/330/500ml 칩 + 직접 입력)과 `+{컵}ml` 버튼.
- 걸음 상세에는 목표 걸음 설정(3000–20000).

### 4. 식단
- 헤더: `식단`(20px/700) + `+ 음식 기록` 주 버튼(36px).
- **빈 상태**: 글래스 카드 안에 캐릭터 96px(불투명 .72, `grayscale(.25)`) + `아직 기록이 없어요` + `먹은 음식을 한 개만 추가해도 피또가 오늘 상태를 알려줄 수 있어요.` + `첫 기록 시작하기` 버튼.
- **식사 슬롯 4개**(아침/점심/저녁/간식): 카드마다 제목 + 합계 kcal, 항목 행(이름 / 양 / kcal), 비어 있으면 점선 `+ {슬롯} 추가`.
- **퍼스널 추천 식단** 카드: 제목 + `땅콩·아몬드 제외` 배지(라벤더 톤). 항목 3개(연어 포케볼 480 / 두부 유부초밥 420 / 단호박 수프 260), 각 46px 썸네일 자리(대각 스트라이프 플레이스홀더 — **실제 음식 사진으로 교체**).
- 하단 2버튼: `나만의 레시피` / `식단 분석`.

**음식 검색 바텀시트**: 상단 그랩바 → 검색 입력(46px, 좌측 🔍, **우측 24px 원형 ✕ 지우기 버튼**) → 최근 검색 칩 → 결과 리스트. 결과 행 = 이름 + 가능/알레르기 배지 + 1회 제공량·메모 + kcal + **우측 `추가` 버튼**(알레르기 음식은 `제외` 회색, 눌러도 추가되지 않고 `알레르기 성분이 포함된 음식이에요` 토스트). 알레르기 행은 배경 `rgba(255,171,145,.14)`, 불투명 .75.
추가 시 저녁이 비어 있으면 저녁, 아니면 간식으로 들어가고 `기록에 추가했어요` 토스트.

내장 음식 데이터(구현 시 공공데이터 영양성분 API로 대체): 닭가슴살 구이 100g 165 / 현미밥 1공기 210g 310 / 그릭요거트 150g 130 / 아몬드 한 줌 25g 145(알레르기) / 땅콩버터 토스트 1장 290(알레르기) / 연어 샐러드 1인분 340 / 두부조림 150g 180.

### 5. 나만의 레시피
- **사진 첨부**: 150px 높이 이미지 슬롯(r18). 실제 앱에서는 카메라/갤러리 선택.
- 레시피 이름 입력(44px).
- **재료 선택**: 자주 쓰는 재료 칩(닭가슴살·현미밥·계란·두부·연어·브로콜리·고구마·아보카도·올리브유·우유·아몬드·땅콩버터) + g 입력(96px) + `재료 추가 (g)` 버튼.
- **직접 입력**: `목록에 없는 재료 직접 입력` 점선 버튼 → 재료명 + 100g당 kcal(필수) + 탄/단/지 g(선택) 입력 후 `이 재료로 추가`. 추가한 재료는 칩 목록에 남아 재사용된다.
- 재료 리스트: 이름 / g / 계산된 kcal / × 삭제.
- **영양 분석 카드**: `룰 기반 · API 연동 예정` 배지. 총 kcal(28px) + 탄수/단백/지방 3칼럼 + 100% 스택 비율 바(탄 blue / 단 mint / 지 lavender) + 코멘트.
  계산: 재료 100g 기준값 × (g/100) 합산. 매크로 칼로리 = 탄×4, 단×4, 지×9.
  코멘트 규칙: 재료 없음 → 안내 문구 / 단백질 비율 ≥20% → 좋음, <20% → 주의 / 지방 ≥40% → 주의, 그 외 좋음 / 알레르기 재료 포함 → 경고 / 총 800kcal 초과 → 2인분 권장.
- `레시피 저장` → 저장 목록에 쌓이고 각 항목에서 `식단에 추가`(오늘 저녁).

내장 재료표(100g 기준 kcal/탄/단/지): 닭가슴살 165/0/31/3.6 · 현미밥 111/23/2.6/0.9 · 계란 155/1.1/13/11 · 두부 76/1.9/8/4.8 · 연어 208/0/20/13 · 브로콜리 34/7/2.8/0.4 · 고구마 86/20/1.6/0.1 · 아보카도 160/9/2/15 · 올리브유 884/0/0/100 · 우유 60/4.8/3.2/3.3 · 아몬드 579/22/21/50 · 땅콩버터 588/20/25/50. (아몬드·땅콩버터 = 알레르기 표시)

### 6. 식단 분석
- **주간 영양 밸런스 카드**: 하루 평균 kcal(26px). 탄/단/지 각 행 = 라벨 + `권장 {n}%` + 차이 뱃지(`+/-n%p`, 차이 ≤6%p면 좋음색·초과면 주의색·부족이면 blue) + 현재 % + 11px 비율 바에 **권장선 마커**(2px 세로선, txt 32% 불투명). 권장 비율 탄 50 / 단 25 / 지 25.

## State Management

영구 저장(로컬 DB / AsyncStorage / UserDefaults):
- `theme`: 'light' | 'dark' | 'system'
- `persona`: 'friendly' | 'strict' | 'neutral'

- `goals`: { kcal(기본 1850), water(기본 1900), steps(기본 8000), cup(기본 250) }
- `periodOn`: boolean
- `cardOrder`: string[] — 기본 `['kcal','water','act','steps','ex','week','period']`
- `cardHidden`: string[]
- `alarms`: { water, waterEvery, meal, mealTimes, move, moveAfter, weigh, report, quiet, quietFrom, quietTo }
- `recipes`: 저장한 레시피 목록, `customIngredients`: 사용자 정의 재료
- 일자별 기록: `water(ml)`, `meals{아침,점심,저녁,간식}`, `exercises[]`, `steps`, 생리 `condition`/`symptoms`
- `onboardingDone`, `tutorialDone`
- `birthdayShownYear`: 축하를 전달한 연도. 생일 배너 노출 여부는 **프로필 생일 = 오늘**로만 판정하므로(당일 내내 떠 있고 몇 번이든 다시 열 수 있다) 이 값이 배너를 막지는 않는다. 올해 축하를 이미 봤는지 기록하는 용도다.
- 온보딩 입력: `obInfo`{ name, gender, age, height, weight }, `obTags`{ health[], taste[], avoid[] } — 직접 입력한 값 포함, `obPick`{ 활동량, 목표, 성격 }

세션 상태: 현재 탭·화면, 열린 시트/모달, 검색어, 기간 선택(range / monthMode / monthOffset / 사용자 지정 시작·종료), 레시피 작성 중 초안, 토스트.

파생값(저장하지 않고 계산):
- 섭취 kcal = 모든 식사 항목 합, 소모 = 기본 320 + 운동 기록 칼로리 합, 남음 = max(0, 목표 − 섭취)
- 칼로리 상태 5단계, 물 단계 5단계(위 규칙)
- 시간대(기기 시각)

## 구현 시 주의
1. **글래스모피즘이 브랜드다.** 블러를 생략하면 이 디자인이 아니다. 카드 배경 반투명 + 블러 + 흰 테두리 1px + 부드러운 그림자를 항상 함께 적용한다.
2. **캐릭터 상태 연동이 핵심 기능이다.** 물 섭취량 → 표정/채도/부유 속도, 성격 → 모든 문구. 이 두 축이 앱 전체에 일관되게 적용되어야 한다.
3. **성격별 문구는 하드코딩 카피가 아니라 문구 테이블로** 관리한다(위 표 그대로 3×N 테이블).
4. 3안(홈 레이아웃 / 물 카드 / 헤더 / 탭바)은 **디자인 탐색 결과**다. **구현 기본값은 홈 B(히어로), 물 B(컵), 헤더 A(페이드), 탭바 B(4탭 + 중앙 FAB)**. 나머지 안은 구현할 필요 없다.
5. 프로토타입 안의 수치·차트 데이터는 예시다. 실제 데이터 소스(건강 API, 걸음 센서, 음식 영양성분 API)로 연결한다.
6. 의료 관련 문구("의료 진단을 대체하지 않습니다")는 **삭제하지 말 것**.
7. 접근성: 최소 터치 44px, 다크 모드 대비 확보, 글씨 크기 조절은 V2 예정이나 **레이아웃은 텍스트 확대에 깨지지 않도록** 고정 높이를 남용하지 않는다.
